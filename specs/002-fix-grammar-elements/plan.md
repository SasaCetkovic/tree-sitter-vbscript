# Implementation Plan: Fix Missing VBScript Grammar Elements

**Branch**: `002-fix-grammar-elements` | **Date**: 2026-03-22 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/002-fix-grammar-elements/spec.md`

## Summary

Fix 4 categories of grammar bugs in `grammar.js` and promote 21 skipped corpus tests to
passing. Root causes: (1) extras regex `\s` consumes newlines needed by `_terminator`;
(2) no `word` property means keyword terminals lose to `identifier`; (3) assignment `=`
parsed as comparison; (4) `hex_literal`, `octal_literal`, `date_literal` absent.
All fixes are applied to the single source-of-truth file `grammar.js`, regenerated with
`tree-sitter generate`, and verified via `npx tree-sitter test`.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| Extras changed from `/[\s\t]/` to `/[ \t]/` (Principle II states MUST include `/[\s\t]/`) | JavaScript's `\s` matches `\n`/`\r`, which prevents `$._terminator` from ever firing. Every block construct (`block_if_statement`, `for_statement`, `while_wend_statement`, `option_explicit_statement`, etc.) requires `$._terminator` to terminate the header line. Without this fix, the entire block-construct grammar is non-functional. | No simpler fix exists: adding `$._terminator` to extras would still fail (it would be consumed as an extra before matching the rule); adding precedence to block rules doesn't help because the token is never produced. The constitution itself contained an error; this fix corrects both the grammar and the principle (constitution amendment needed to update `/[\s\t]/` to `/[ \t]/`). |
